# NEO FIT 3.0

Личный сайт для тренировок, питания и ежедневных записей. Цветной адаптивный интерфейс, отдельные профили, автоматическое сохранение. Скачивать HTML после тренировки больше не нужно.

**Статус поставки:** приложение опубликовано на https://upneo.github.io/neo-fit/ и подключено к отдельному Supabase `neo-fit`. GitHub Actions выполняет проверку, тесты, обязательную облачную сборку и публикацию Pages. Результаты исходных проверок: `docs/TEST_REPORT.md`; фактический production-запуск дополнительно проверен 17 сентября 2026 года.

## Что здесь есть

- Программы, текущая тренировка, веса/повторы/RIR, таймер, история и отчёт для тренера.
- Добавление упражнения по ходу и после занятия; замена только выбранного упражнения, поиск похожих движений и редактируемая техника. Ссылки открывают именно поиск YouTube/Яндекса, а не проверенный ролик.
- Четыре нейтральные редактируемые основы программы после входа и каталог из 87 упражнений: синонимы, мышцы, оборудование, сложность, техника и два режима замены. Рабочие веса не назначаются.
- Добавки и отдельный журнал пептидов: форма, единицы, разные количества по времени, связь с едой, календарь фактов и версии расписания. Никаких готовых курсов, дозировок, разведений или компенсации пропущенных доз.
- InBody: локальное чтение поддерживаемого PDF, SHA-256 от дублей, ручной ввод, история, сравнение, фильтры графика, дополнительные показатели, диапазоны источника и сегменты тела. Исходный PDF не загружается.
- Анкета, замеры веса, ориентировочный расчёт питания, ручные цели и фактические записи. Генератор стартовой программы — прозрачные фиксированные правила, не ИИ-врач и не персональное назначение.
- Логин и пароль, приглашения для друзей, разделение данных на сервере. В коде нет готовых действующих аккаунтов, паролей или личной истории.

## Запустить на своём компьютере

Нужен Node.js версии 22 или новее. Зависимости устанавливаются командой `npm ci`; PDF.js поставляется локально и не отправляет PDF во внешний сервис.

```sh
npm run dev
```

Открой `http://127.0.0.1:5173`. На Windows можно запустить `START-WINDOWS.cmd`: он покажет адрес и запустит тот же сервер. Не открывай `src/index.html` двойным щелчком — это модульный сайт, а не старый переносимый HTML.

При пустой облачной конфигурации создай **локальный** профиль, выбери программу и оцени интерфейс. Изменения сохраняются автоматически в зашифрованном хранилище этого браузера. Это не облако; очищение данных браузера удалит эту копию. Адрес и профиль браузера должны оставаться теми же. Тестовые локальные профили не регистрируются в Supabase сами собой.

```sh
npm run check
npm test
npm run build
npm run preview
```

## Размещение по обычной ссылке

Для сайта нужен новый репозиторий, а для облачных личных записей — **отдельный новый проект Supabase**. Существующие чужие проекты, например магазин или другой бот, не используй.

Пошаговая инструкция: **`docs/DEPLOY.md`**. Основные этапы:

1. Подготовить отдельный Supabase: таблицы/RLS из миграции, функцию регистрации, серверный код приглашения.
2. Загрузить этот проект в новый репозиторий GitHub. В Variables задать `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`.
3. В Settings → Pages выбрать GitHub Actions. Workflow соберёт сайт, проверит настройки и опубликует `dist/`.
4. Создать облачные профили через приглашение и один раз перенести прежние записи.

**Публикация намеренно останавливается, если база не настроена.** Она не подменяет облачный сайт локальными профилями без предупреждения.

Дополнительный вариант: `npm run publish:github` на компьютере владельца, где уже есть Git и GitHub CLI с авторизацией через `gh auth login`. Скрипт просит явное подтверждение, создаёт только новый публичный репозиторий, отправляет только разрешённые файлы и не меняет существующий `origin`. Он не создаёт Supabase и не знает твоих токенов. Подробности в инструкции.

## Один раз перенести старые записи

Файл `NEO-FIT_private_transfer.json` выдан отдельно от проекта. Это зашифрованные прежние профили. **Не добавляй его в репозиторий или `dist/`.** Пароли у него такие же, как у прежней личной NEO FIT HTML-версии.

В новом аккаунте открой «Профиль» → блок резервных копий/импорта → **полное восстановление**, выбери личный JSON, затем свой профиль внутри него и пароль старой копии. После подтверждения будут восстановлены программа, история и другие записи; логин текущего аккаунта сохранится. Эта операция выполняется **один раз**, не после каждой тренировки. При наличии новых записей сначала сделай резервную копию или выбери объединение истории вместо полной замены.

Можно импортировать и старый HTML: приложение извлекает из него только JSON, не выполняя код файла. После переноса HTML больше не нужен для повседневной работы. JSON-резерв остаётся дополнительной страховкой, а не обязательным способом сохранения.

## Как устроено сохранение

Изменение поля ставится в очередь автосохранения. Статус «Сохранено в облаке» появляется только после успешного ответа сервера. При потере соединения остаётся зашифрованная ожидающая копия на текущем устройстве и виден статус ожидания. Восстановление сети повторяет отправку, если нет конфликта.

Сервер использует проверку версии: устаревшая вкладка не перезаписывает новые записи молча. Раздел «Профиль» позволяет сохранить свою копию и явно загрузить серверную. Обновления с другого устройства проверяются примерно раз в 30 секунд и при возвращении на вкладку, когда нет несохранённых изменений или открытой формы. Ввод в активную форму не перезатирается автоматически.

Токены входа не попадают в публичные файлы. При включённом «Запомнить вход» сессия хранится в namespaced localStorage, иначе — в sessionStorage; личный offline-кэш зашифрован отдельным случайным ключом устройства. Refresh-токен обновляется через Supabase Auth. При реальном отзыве/истечении сессии приложение очищает локальную авторизацию и просит войти снова.

## Стек и структура

Нативные JavaScript ES-модули, CSS, JSON, Node.js для сборки; Supabase Auth, PostgreSQL JSONB + RLS и серверная регистрация на TypeScript. Никакого платного внешнего ИИ API. React не используется: для этого масштаба не нужен дополнительный runtime.

```text
src/main.js                     интерфейс и взаимодействия
src/lib/domain.js               упражнения, календарь, миграции, расчёты
src/lib/storage.js              шифрование, локальное и облачное сохранение
src/lib/bootstrap.js            загрузка конфигурации и JSON-каталогов
src/lib/inbody.js               распознавание поддерживаемого текста InBody
src/ui/studio.css               цветная дизайн-система и адаптивность
src/data/                       публичные программы и каталог, без результатов
scripts/                        локальный сервер, сборка, публикация
supabase/                       SQL, RLS-тесты и функция регистрации
.github/workflows/pages.yml     проверка, сборка и публикация Pages
```

Текущая схема личного JSON — `schemaVersion: 3`. Документы v2 автоматически обновляются в памяти клиента с сохранением программ, истории, черновика и неизвестных полей; сервер не допускает обратный откат v3 → v2. Номер приложения — 3.0. Исходная HTML-оболочка есть, как у любого сайта, но данные больше не записываются внутрь неё.

## Ограничения и безопасность

Смотри `docs/SECURITY.md`. RLS, изоляция владельцев, отказ анонимному доступу и конфликт версий проверены на отдельном production-проекте. Уведомления при закрытом сайте не реализованы; есть необязательный `.ics` для календаря. Калораж — приблизительный ориентир; журнал приёма не проверяет совместимость и не назначает лечение.
