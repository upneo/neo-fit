# Границы безопасности и хранения

## Какие данные публичные

Код интерфейса, общий каталог упражнений, общие шаблоны программ, URL Supabase и publishable key. В репозитории нет личной истории и действующих пользовательских паролей. Публичность оболочки не должна означать публичность записей.

## Личные записи

Локальный режим: AES-GCM, PBKDF2-SHA256 (600000 итераций), отдельная соль, случайный IV, отдельная запись профиля. Пароль остаётся только в памяти операции входа. Облачная сессия сохраняется в localStorage только при явном выборе «Запомнить вход», иначе в sessionStorage; offline-кэш документа шифруется отдельным случайным ключом устройства. Шифрование не защищает от вредоносного кода в уже открытом профиле, небезопасных расширений или слабого пароля. Очистка данных браузера удаляет локальную копию.

Облако: Supabase Auth + проверка владельца сервером, RLS на чтение, запрет прямых клиентских записей, RPC с auth.uid() и проверкой версии документа. Клиент не выбирает user_id для записи. Данные внутри PostgreSQL доступны администратору проекта: **это не end-to-end encryption от владельца сервера**. Зашифрованный кэш ожидания на устройстве — отдельный механизм.

## Что не отправлять в GitHub

Личные JSON/HTML, `.env`, service_role/secret keys, приглашение, пароли, реальные email/учётные данные. Сборщик отвергает service_role и sb_secret. Скрипт локальной публикации использует список разрешённых папок, а не `git add .`. За изменение файлов внутри разрешённых папок после выдачи проекта отвечает владелец.

Отдельно выданный `NEO-FIT_private_transfer.json` не должен лежать в `src/`, `public/`, `dist/` или репозитории, несмотря на шифрование.

## Конфликты и ограничения

Используется compare-and-swap, а не автоматическое слияние одновременно изменённых полей. При конфликте обе версии нужно разобрать явно. Если сервер принял запись, но ответ потерялся, повторная отправка может вызвать конфликт — версия не перезапишется молча. Полная CRDT/offline-first синхронизация в эту версию не входит.

Черновик в открытой вкладке можно продолжать при потере связи. Для нового входа в облачный аккаунт нужен интернет. Сессия восстанавливается до показа формы входа и обновляется refresh-токеном. При offline-сбое зашифрованная ожидающая копия сохраняется; при подтверждённом отказе Auth локальная авторизация очищается. Старая password-derived копия мигрирует только после следующего успешного входа и не удаляется при ошибке.

Облачный snapshot ограничен 5 МБ. Это небольшой личный дневник, не многопользовательская медицинская платформа. Импорт ограничен по размеру, данные проходят проверку, код из старого HTML не выполняется.

Регистрация по длинному общему коду подходит для маленькой закрытой группы, но не заменяет полноценное управление одноразовыми приглашениями. Лимитер функции — только best-effort внутри экземпляра. Для публичного запуска на большую аудиторию нужны глобальные ограничения попыток, дополнительные проверки и аудит.

Текущие резервные копии шифруются выбранным паролем. Смена пароля не меняет уже выгруженные старые копии. Автоматического восстановления забытых паролей через почту нет: технические адреса не принимают письма.

Service Worker сохраняет только публичную оболочку из whitelist. Ответы Auth/REST и личные документы не попадают в Cache Storage. Новая версия оболочки не активируется принудительно посреди открытой тренировки.

## Здоровье

Журнал приёма — только учёт самостоятельно введённых сведений. Он не подбирает препараты/пептиды, не рекомендует дозировки и не оценивает взаимодействия. Нет схем разведения, инъекций или удвоения после пропуска. Количества сохраняются текстом с единицами, без конвертации мг/мкг/мл/делений.

Питание — оценочный калькулятор с ручными целями, не измерение энергозатрат. Памятки по технике общие и редактируемые; поисковые ролики приложением не проверяются. Нет обещаний отсутствия травм или индивидуальной медицинской пригодности.

## InBody и уведомления

PDF InBody разбирается локально через PDF.js; оригинал не отправляется в Storage и не попадает в Cache Storage. В документ записываются только выбранные показатели, дата, источник и SHA-256. Системные уведомления таймера включаются только пользовательским жестом. Серверный Web Push не развёрнут: для него потребовался бы отдельный явно одобренный контур с service-role и внешним egress к push endpoint.
