# Проверка NEO FIT 3.0

Дата проверки: 17 сентября 2026. Это отчёт о выполненных проверках, а не сертификат безопасности или медицинской пригодности.

## Автоматические проверки

**51 автоматический тест — пройден** (`node:test`):

- миграция schema v2 → v3 без потери неизвестных полей, программ, истории и черновика;
- непрерывная очередь тренировок с повторяющимися шаблонами и явным пропуском;
- упражнения по сторонам, секунды вместо повторов, десятичные веса и защита введённых результатов при замене;
- 87 упражнений и четыре нейтральные основы программы без назначенных рабочих весов;
- структурированные добавки, разные количества по времени, версии расписания и неизменяемые прошлые факты;
- InBody: разбор поддерживаемого текста, защита от дублей и отсутствие автоматической замены веса профиля;
- AES-GCM/PBKDF2, смена пароля, изоляция локальных профилей и конфликт двух вкладок;
- восстановление remembered-сессии до показа формы входа, refresh/JWT и отдельный зашифрованный offline-кэш;
- запрет публичной сборки с service_role/secret key и обязательная облачная конфигурация production;
- безопасная активация Service Worker только по кнопке и отсутствие Auth/REST в shell-cache;
- отсутствие личной истории, секретов и старого HTML-экспорта в публичной оболочке.

Команды `npm run check`, `npm test` и `npm run build -- --production` завершены успешно. Production-сборка содержит только whitelist публичных файлов и локальную поставку PDF.js.

## Проверка интерфейса

В Chromium проверены настоящие модули и обработчики приложения:

- восстановление интерфейса без горизонтального переполнения во всех девяти разделах на ширине 360 px;
- поля пароля входа, регистрации, повтора и смены пароля скрыты по умолчанию;
- кнопки-глаза переключают состояние в обе стороны, меняют `aria-label` и не перекрывают ввод на мобильной ширине;
- современный HTML-паттерн логина принимает допустимые дефис и подчёркивание без ошибки RegExp;
- реальный поддерживаемый InBody PDF распознан локально: предварительный просмотр нашёл 17 показателей, 9 диапазонов источника и 10 сегментов с проверенным лево/право; повторный импорт был остановлен как дубликат, вес профиля не изменился;
- локальная production-сборка загружается без ошибок консоли.

Service Worker не регистрируется при обычном HTTP-просмотре. Его регистрация, контроллер и shell-cache проверяются отдельно на опубликованном HTTPS-адресе после GitHub Pages deploy.

## Supabase

На production-проекте применена миграция schema v3. Сервер принимает v2/v3, требует новые поля v3 и не допускает откат сохранённого документа с v3 на v2. Владелец по-прежнему определяется через `auth.uid()`, а запись выполняется compare-and-swap RPC.

Перед изменениями создана приватная резервная копия серверных документов. После миграции подтверждены сохранность документов, наличие ограничения schema v3 и защита от downgrade. Импорт InBody в существующий аккаунт Neo выполнен идемпотентно и серверно подтверждён как единственная запись с уникальным хешем; исходный PDF в Storage и репозиторий не загружался. Курс пептидов не создавался.

Supabase performance advisor не сообщает замечаний. Security advisor оставляет два предупреждения: намеренно доступный авторизованным пользователям `SECURITY DEFINER` RPC `save_diary` и отключённая проверка скомпрометированных паролей.

## Оставшиеся ограничения

- Серверный Web Push для полностью закрытого приложения не развёрнут: требуемый контур с service-role и внешним egress не был одобрен. Локальные уведомления таймера и экспорт `.ics` остаются доступны.
- Установка PWA, фоновые уведомления и поведение на физических iOS/Android устройствах не проверялись.
- Полный независимый аудит безопасности и соответствия WCAG не выполнялся.
